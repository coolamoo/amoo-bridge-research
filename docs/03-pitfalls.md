# 03 · 踩坑清单

按「踩到时浪费的时间」排序。

## 1. 控件树坐标和触控坐标不是一回事

同一时刻 dump 出来的节点：

```
{"t":"存在","y":2152, "bounds":[188,2100,449,2204]}
```

而这个按钮在屏幕上的真实位置是 **y≈1580**。差值约 570 px，方向和幅度稳定。

后果：`do tap by=text` 会「成功定位、点击、但页面毫无变化」（`NOT_VERIFIED`）。
看起来像点了，其实点在空白处。

**规则：树坐标只用来判断「有没有这个元素」，点击坐标一律从截图量。**

## 2. 一输出文字，前台就被抢

只要助手在两条命令之间说话，聊天界面就回到前台，目标 App 退到后台。
表现是下一条命令的回执里 `appBefore == 聊天包名`，`located.nodeText` 匹配到的是聊天消息文本。

更隐蔽的版本：`do tap by=text 存在` 把聊天记录里的「存在」当目标，`matches: 2`。

**规则：连续动作打包成一条 chain，链内不输出任何文字。**

## 3. OCR 在 H5 / 游戏画面上是废的

同一个引擎：
- 原生列表页：正常读出「300 金条」「分享」「战果」；
- 游戏画布 / H5 答题页：`"人 一 AN @"`、`"@@@"`、`"08:18 团 国 罗 1 全 口 g3，"`。

`region` 缩小 + `zoom:2` 不但没用，还会 18 ms 返回空数组（参数被忽略）。
H5 页面上 `dump` 也几乎是空树（只有几个无标签 View）。

**规则：这类页面直接截图交给视觉模型，不要指望 OCR。**

## 4. 桥会悄无声息地死

症状：命令写进去了，`res` 一直不出现，`in/` 目录越积越多。
原因是带前台服务的 App 被系统回收。

**规则：任何「命令超时」先做一次存活判定（in 有 cmd / out 无 res），
让用户点桌面图标重启，积压命令会自动补跑。**

## 5. 悬浮小窗会裁掉底部导航

高德在小窗模式下，窗口 bounds 类似 `[138,307,1062,2040]`，
底部「招募/寻宝/前进/任务/道具」会被裁在可视区外，表现是「前进按钮时有时无」。

**规则：先切全屏，再操作底部按钮。**

## 6. back 的语义是「全局返回」，不是「关弹窗」

在游戏页按一次 `back` 可能直接退出整个 App 回到桌面。
想做「关掉弹窗」时，优先找弹窗自己的关闭按钮；找不到再 `back`，并且只按一次就复核。

## 7. 输入框打字前必须确认焦点

`text` op 在没有焦点输入框时返回 `no focused input`，不报错但什么都没发生。
顺序必须是：点输入框 → 等键盘起来 → 再 `text`。

## 8. `launch` 只是「拉起」，不保证回到你以为的页面

App 会恢复到上次停留的页面。可能是大富翁游戏页，而不是首页。
所以链开头要留一步 `back` 或者一次 `dump` 复核，不要假设。
